# Gemma 4 Developer Agent — candidate comparison

This report compares agent-configuration candidates for [`gemma-4-developer-agent`](https://www.kaggle.com/competitions/gemma-4-developer-agent). It is generated by `solutions/gemma_4_developer_agent` and is fully reproducible from the repository.

> **What is and is not measured here.** The official score is the percentage of hidden repository issues whose validation tests pass after applying the submitted patch. Producing that number requires the organiser's harness: a Docker sandbox, the `gemma-4-31b-it-qat-w4a16-ct` weights and the hidden task set. None of that is available offline, so **no candidate here has an official score, and none is claimed.** What this package does measure is (a) whether a candidate survives the harness's *upload gates* and (b) how well its engineering matches the failure modes the competition itself documents. Section 5 states the limits of that substitution explicitly.

### What the proxy cannot see

- It does not run the candidate's prompt against Gemma 4, so it says nothing about model behaviour, tool-call validity under 4-bit quantisation, or patch correctness on real issues.
- Candidates that ship no scripts are scored `n/a` rather than zero, and receive the neutral prior 0.50 in the composite. A prompt-only agent can perform well in the real harness; it simply provides nothing verifiable offline.
- Skill-script correctness is necessary but not sufficient: a perfect `patch_hygiene` script cannot fix a wrong hypothesis about the bug.
- The fixture repos are three files. They test that the machinery works, not that it generalises.
- **The ladder and the rubric share provenance.** The candidates were designed from the failure boundaries the rubric encodes, so the top candidate saturating the rubric is an expected consequence of that design, not independent confirmation that it will score well. The proxy is the only signal here that could have contradicted a claim -- and it did not, which is evidence about the shipped scripts and nothing more.

4. Do not treat the composite ordering as a leaderboard. It orders *engineering quality*; only the harness can order *task pass rate*.
